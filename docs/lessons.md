# 这次制作的复盘

## 角色一致性比一次画很多动作更重要

人物从照片转成卡通后，还需要一个统一的标准形象。每个动作都附上同一参考，才更容易保留小熊猫发箍、服装、发型与持物手。角色太高、头发太散或饰品过细，会让小尺寸的动作条难以提取。

## 跳跃原图正确，提取结果也可能错误

这次原始跳跃动作有明显起跳位移，但默认按每个连通域裁切并居中后，所有帧重新对齐到相同高度，实际播放像换了姿势而没有离地。

修复采用上游 `extract_strip_frames.py --method stable-slots`：保留共享视口、统一尺度和原图垂直位移。之后重新生成 GIF 和接触表，复核真正的腾空与落地。

## 生成模型会加上“可爱但不适合精灵”的装饰

等待动作的一版出现了悬浮爱心和问号，工作动作的一版出现了平板。它们不属于标准形象，会导致连通域提取或道具一致性问题。

修复方式是重做对应的一整条动作，明确“只用身体和表情表达；不加新道具、符号或悬浮效果”。头饰上原本的爱心贴片则需要保留，不能把身份特征一起删掉。

## 左上与右上很容易画反

制作十六个视线方向时，一版最后三帧从向左看突然变成向右上看。单看每张图都很自然，但放进顺时针循环就发生反转。

先确认四个基本方向，再强调 **屏幕左/右**，检查鼻尖、眼睛和头部朝向。在接触表里按顺序查看整条循环，比只看单帧可靠。镜像不能随便用于带有单手挂件的人物。

## 源图有留白，不代表最终格子一定不会裁切

视线第十行需要沿用第九行登记的共享尺度。来源人物稍大时，即使来源画布边缘有空白，登记后的头发仍可能靠近最终单元格边缘。解决方式是重新生成比例匹配的整行，而不是放宽错误门槛。

## 文件安装与界面选中是两个步骤

将精灵图与 manifest 放入本地目录，只代表包已就位。直接修改正在运行的应用的内部选择配置，可能被应用覆盖，不能当作切换成功的证据。这次第一次尝试便出现了这种情况。

因此公开的安装脚本只安装文件，并明确提示在应用的宠物设置中刷新和选择；不复制当时临时读取应用内部资源或改写内部状态的调试代码。

## 最终验收状态必须如实记录

九组标准动作完成了检查，跳跃也修复过。使用者随后要求跳过修正版最终全套验收并直接安装，因此示例不宣称所有视线方向与连续性都已通过最终验收。仓库保留了相应工具与复核方法，便于后续完善。
